# DoseTrace — Top 10 gaps found (draft, 27 Sep 2026)

Read-only review of `main` @ 902c9ea. Each item cites where to look. Ordered by risk to users, then by release impact.

1. **Mixing a new vial still rewrites the protocol's history (HIGH).**
   The 13 Sep journey review confirmed this defect and wrote the fix: "don't write start_date in createNewVial". It is still there. `screens/TodayScreen.js:805` runs `updateProtocol(continuationProtocol.id, { start_date: mixDate })`. The serum curve, adherence, streaks and reminders all count from `start_date`, so opening a fresh vial erases everything before it. This breaks the "never lose user data" rule. No test. (App map L-13; features A-06.) The same review's F3 fix wasn't done either: the curve disclaimer still says the model uses "your logged doses" (`i18n/translations.js:570`, and the same in the other 5 languages), but the curve uses the schedule.

2. **The app still calls the test AI function, and the server copy of the reminder rules has drifted.**
   `lib/nutritionClient.js:10` is `FOOD_FN = 'parse-food-next'` (the isolated test copy). The handoff lists "point the app back to parse-food, deploy v9" as a release step. If it's forgotten, 1.2.5 ships against a test endpoint. Separately, `supabase/functions/send-reminders/plan.ts` says "keep the two identical" but still has the old food rule (every-other-day backoff, stop at day 21, skip logged days). The client (`lib/notificationPlan.js` `foodNudgeDays`) follows FL-18/FL-42. It's dormant now, but it will misfire when server push is switched on. (A-03, A-04, L-48.)

3. **An approved 1.2.5 item isn't in the code: the iOS build doesn't declare its 6 languages.**
   `app.json` has no `ios.infoPlist.CFBundleLocalizations`, and `ios/DoseTrace/Info.plist` only sets `CFBundleDevelopmentRegion`. So the App Store keeps listing the app as English-only. The screenshot 01 swap + order fix is also committed to 1.2.5 but can only be done in App Store Connect once the 1.2.5 version exists. Nothing in the repo tracks it except STATE.md. (A-01, A-02.)

4. **"Mark as taken" is written twice, and the two versions already behave differently.**
   `TodayScreen.js` `markTaken` and `lib/doseActions.js` `recordDoseTaken` (the notification button) each insert the dose log and update the vial and oral counts. The second even says it "mirrors TodayScreen.markTaken". The notification path has a double-log guard and turns an existing "Missed" row into "Taken". The Today path does neither, so tapping Take on a slot that was already auto-marked Missed can leave two rows for one dose. Neither path has a test. (L-07, L-08.)

5. **Two "supply low" rules that disagree.**
   The Today alert fires at ≤3 doses left and works out the vial size when `total_doses` is empty (`TodayScreen.js` `SUPPLY_LOW_DOSES = 3`, ~line 1030). The push notification fires at ≤2 and skips any vial without `total_doses` (`lib/notifications.js` `syncVialAlerts`, line 428). Older vials therefore get the in-app warning but never the push. There's also a second schedule implementation: `notificationPlan.dueDateKeys` honors `schedule_total` and `schedule.expectedDosesOn` doesn't. It's harmless today because new protocols save `schedule_total: null`, but it's the same drift pattern. (L-03, L-11, L-12.)

6. **Premium is checked two different ways.**
   Strict `isPremium()` (`lib/purchases.js`) returns false whenever RevenueCat can't be reached. It gates the serum curve, Progress, target ETA, PDF export, lab uploads and the 3-protocol limit. The food log instead uses the lenient `resolveEntitlement` (`lib/foodThread.js`), which remembers the last known state. A paying user who is briefly offline sees the curve locked while the food log stays open. Also, free users get the 7-day reality check (FL-41), but Progress snapshots stay strict-Premium (`CalculatorSection.js` ~line 1250). Their weigh-ins can't feed the target ETA, which is one of FL-41's open founder questions. No test covers the strict gating. (L-24, L-34.)

7. **Changing sex or birth year in Settings may not reach the BMR.**
   `CalculatorSection.js` `load` (lines 223–236) first takes `gender`/`birth_year` from the profile, then lets `calc_inputs.sex` and `calc_inputs.age` override them. It re-saves them on every edit (line 280). So once a user has used the calculator, a later profile change of sex is ignored by the math (the sex gate still reads the profile, so the two can disagree), and age never goes up with birthdays. That's two sources of truth for the same fact. No test covers the wiring. (L-29, L-30.)

8. **The open reality check and calculator inputs still live only in user_metadata + AsyncStorage, against CLAUDE.md.**
   CLAUDE.md says reality-check and calculator inputs "must move to durable synced storage". `lib/realityCheck.js` still keeps the open weigh-in in AsyncStorage plus `user_metadata.calc_reality_open`, written fire-and-forget (an offline Stop may never reach the cloud). Reads are local-first, so stopping a check on one device leaves the other device's Today alert and 8 PM reminders running. Reality-check weigh-ins are also never saved as Progress snapshots, so they don't feed the target ETA or the start-weight pre-fill. `lib/realityCheck.js` has no test. (A-13, L-20, L-21, L-31, L-47.)

9. **The food-log rebuild (the headline of 1.2.5) isn't done by its own standard.**
   `docs/specs/food-log.md`: 7 of 46 rows are `built` (FL-1, 2, 5, 11, 12, 17, 25) and 39 are `partial`. FL-13, FL-14 and FL-22 are marked OPEN, and FL-41 has two open founder questions. `scripts/spec-audit.cjs` fails on any partial row without an approved deviation, so the build gate is (correctly) red. The handoff also says main is at c8ec113, but main is now at 902c9ea (one more audit-fix commit). Anyone working from the handoff is one commit behind. (A-05.)

10. **Nothing tests the connections between tabs.**
    All 17 files in `__tests__/` test pure functions or the sync harness. None renders a screen, drives navigation or runs a notification handler, and the "Tier 3/4" component and Maestro tests were deferred long ago. 24 of the 50 cross-tab links in `app-map.md` have no test, including mark-taken, the vial prompt, premium gating, notification taps and "Stop reality check". The wiring of the food log → reality check → Your goal chain (L-17/L-18) is only covered piece by piece. This is exactly the "connections break in long sessions" problem. The five suggested first tests at the end of `app-map.md` would cover the riskiest ones.

### Also noticed (smaller)
- Exports (`lib/database.js` `getAllDataForExport`, used by My Body and Settings) leave out food_logs, reality_checks, calc_snapshots and calc_targets.
- Two taps have no route in `App.js`: the morning-summary and vial-low notifications.
- `TodayScreen.js` new-vial flow uses `parseFloat(continuationProtocol.water)`, not `parseDecimal`, so a comma-decimal "2,5" becomes 2 (CLAUDE.md gotcha).
- `docs/APP-HANDOFF.md` is stale: it says 3-day free trial, puts the body map in My Body (it's in Today/Log), still mentions CompleteProfileScreen, and lists 8 synced tables (it's 9).
- `BodyScreen.js` uses the text symbols ★ ☆ ✎ (lines 894, 965, 986, 1018). They aren't emoji strictly, but they may break the "no emoji / use FeatureIcon" rule.
- The 1.2.5 "two developer/premium accounts": both new emails are already in `lib/purchases.js`. Which two the handoff means, and whether the 1.2.4 binary already has them, is unclear (F-087).
