# i18n native-quality review — 2026-10-15

Scope: every user-facing string added or changed since build 48 (base `59bf398`) up to HEAD `a9897bb` on
`redesign/graduated`, plus the uncommitted working-tree change (new `settings_privacy_body` x6).
Sources: `i18n/translations.js` (31 changed/added keys + the privacy policy), `locales/*.json` (new iOS
per-language permission texts and app name), `app.json` (English permission texts), and the parse-food
prompt line (`supabase/functions/parse-food/index.ts`).
Read-only review. No source file was edited.

Method: each key was grepped to its screen, the surrounding code was read, and each language was compared with
the app's existing terms in that language (counted across `translations.js`). What was checked: meaning,
native register, consistent terms, placeholders and plurals, no advice, and length. All placeholders
(`{n}`, `{date}`, `{when}`, `{kcal}`) match English in every language; this was checked by script. No string
gives medical advice or interprets anything.

Not counted: `faq_categories` came up in the diff only because arrays compare by reference. Its content is
the same as at the base commit. Four keys were removed (`rc_setup_open`, `rc_setup_later`,
`body_starred_latest`, `body_next_due`), and no code references them any more.

App terms used as the reference (existing strings):

## 8. parse-food prompt — language rule for the ask options

Current line (appended to both the parse and the follow-up system prompt):

```
The user writes in language code "${lang}"; food names may stay in their language. Write every "ask" option (preparations, sizes, amounts, units) in that language ("cozido", not "boiled"); brand names stay as named.
```

Problems:

1. **The Portuguese example goes to every language, English included.** For `en` the rule reads "write in
   English ('cozido', not 'boiled')", which contradicts itself. The model may treat "boiled" as forbidden or
   start using Portuguese.
2. **It pulls Spanish toward the wrong word.** The nearest Spanish word to *cozido* is *cocido*, which in Spain
   is a stew dish. Boiled is *hervido*. Italian *cotto* means "cooked", not boiled (*bollito / lessato*). The
   example is Portuguese-shaped and nudges the other Romance languages toward look-alike words.
3. **The language is only a 2-letter code.** `pt` does not say Brazilian, and the app is pt-BR (*xícara*, not
   *chávena*; *você*). Naming the language helps the model more than the code alone.
4. **The main prompt is full of English option examples** ("regular/large", "fried/grilled", "1 cup"). They come
   before the language line and are the strongest pull back to English. They should be marked as examples of
   the kind of answer, not of the words.
5. "food names may stay in their language" is ambiguous: their = the user's or the food's? This is minor.

Proposed wording. It is language-neutral, gives an example in the user's own language, adds no example for
English, and keeps `__tests__/foodAskLanguage.test.js` passing (the line still contains
`The user writes in language code`, `"ask" option` and `${lang}`, and stays right after `const system =`; the
two maps are declared above `Deno.serve`):

```ts
const LANG_NAME: Record<string, string> = { en: 'English', es: 'Spanish', pt: 'Brazilian Portuguese', fr: 'French', de: 'German', it: 'Italian' };
const BOILED: Record<string, string> = { es: 'hervido', pt: 'cozido', fr: 'bouilli', de: 'gekocht', it: 'bollito' };
...
      + `\n\nThe user writes in language code "${lang}" (${LANG_NAME[lang]}). Write every "ask" option (preparations, sizes, amounts, units) in ${LANG_NAME[lang]}, the way a native speaker says it${BOILED[lang] ? ` (for example "${BOILED[lang]}", not "boiled")` : ''}, even though the examples above are in English. Keep food names as the user wrote them and brand names exactly as named.`
```

Why this works: each user only ever sees an example in their own language, so nothing pulls one language
toward another. English gets no example and no contradiction. "even though the examples above are in English"
deals with point 4 without rewriting the main prompt. Item `unit` values already work in all 6 languages
(`lib/nutrition.js` COUNT_UNITS / MEASURE_UNITS contain *barra, porción, xícara, taza, tasse, Riegel,
porzione…*), so translated units do not break the log display.

The founder approved deploying the current line. This proposal would be a follow-up change to that approved
fix. It needs its own go, and a redeploy of `parse-food`.

## 9. Systematic issues

New in this change set:

1. **Meaning drift on the Android battery setting** (today_alert_battery_body, 5 languages). "Remove the
   restriction" was used where the phone shows *Optimized* and the user must pick *Unrestricted*. When a
   string tells the user to change a phone setting, it must name the option exactly as the app's own row does.
2. **Telegraphic noun stacks in the reality-check alert** (today_alert_rc_needs_food x2, all 5 languages).
   "days in a row of food" was copied from a clumsy English source. Fix the English first, then use each
   language's food-log term.
3. **Policy and alerts not using the app's existing terms.** Bottle: es *frasco*, de *Flaschen*, it *boccette*
   in the policy, against *envase / Packung / confezione* everywhere else. Check-in reminders: 4 different
   inventions in the policy, against the Settings label. Spanish "mixed": *reconstituido* against *mezclado*.
   Spanish "check": *revisar* against *comprobar* on the same screen.
4. **German typography.** The new German strings use "—". German uses a spaced en dash "–", as the app's other
   German strings do.

Already in the app (not part of this change; for the registry):

5. **Vaccine card has 2 words in es and it.** es *cartilla de vacunas* (7 strings) vs *cartilla de vacunación*
   (permission texts, FAQ). it *tessera vaccinale* (6) vs *libretto vaccinale* (permission texts, FAQ,
   vax_scan_premium_sub). Recommendation: one term app-wide, es *cartilla de vacunación* and it *libretto
   vaccinale* (the more common native names).
6. **es bottle:** protocols_container_units_hint says *frasco* where every other bottle string says *envase*.
7. **fr mixes app/appli and appuyez/touchez,** even within the reminder screen (rc_setup_intro "l'appli",
   rc_alarms_sub "l'app"). Pick one of each.
8. **de/it Settings name:** the tab is "Optionen" / "Opzioni", the screen title is "Einstellungen" /
   "Impostazioni", and rc_reminders_off / rc_silent_on say "Optionen" / "Opzioni".
9. **Android's own label for "Unrestricted"** (rc_battery_ok) has not been checked against the phone in
   de/fr/it. I believe stock Android German shows "Nicht eingeschränkt" (the app says "Uneingeschränkt"), but
   I have not verified this. Read it from the Fold's resources, as was done for the Samsung names.
10. **Samsung labels in Spanish come from es-US resources,** while the app's Spanish leans Spain. Check on an
    es-ES phone.
