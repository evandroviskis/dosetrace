Painel admin · 3.1 Entrada com login

Como o painel pede acesso hoje e como ficaria a entrada com conta, senha e código de 6 dígitos. Cada tela aparece no tema claro e no escuro, com as cores do próprio painel (web/adm.html). O texto principal está em português; os outros 5 idiomas aparecem em letra pequena sob cada tela. Nada foi construído: é só a imagem para o senhor escolher.

Para você decidir

  1. Qual conta entra no painel?
    (a) Uma conta nova, só para o painel (um endereço que o senhor escolher), com senha e código.
    (b) A sua conta do app.
    Recomendação: (a). O acesso de administrador fica separado dos seus dados no app; se a senha do app vazar, o painel continua fechado. A conta nova é marcada como conta de teste e não entra em nenhum número.
  2. Por quanto tempo a sessão vale?
    (a) Até fechar a aba ou 8 horas. (b) Até fechar a aba ou 12 horas. (c) Só até fechar a aba.
    Recomendação: (b) 12 horas. Cobre um dia de trabalho sem entrar de novo. As alterações (Premium, marcar teste, reenviar e-mail) pedem um código novo depois de 15 minutos de qualquer forma.
  3. Reserva para o código de 6 dígitos
    (a) Dois autenticadores cadastrados: o do celular e o do gerenciador de senhas.
    (b) Um só; se o celular se perder, o código é removido pelo painel do Supabase e cadastrado de novo.
    Recomendação: (a). O Supabase não oferece códigos de recuperação. Com um segundo autenticador, perder o celular não tranca o senhor fora do painel.

Já decidido

  • O login vem antes de qualquer alteração pelo painel (ordem do senhor, 21/10: login → Premium → aba Usuários → …). O token compartilhado de hoje não identifica quem agiu.
  • E-mail, senha e código de 6 dígitos (TOTP), com a lista de contas autorizadas no servidor. Uma conta fora da lista não recebe nenhum dado.
  • O pedido de token some na mesma entrega (regra "refazer = substituir"). Se o login falhar, volta-se à versão anterior na Vercel, sem uma segunda porta.
  • Nenhuma configuração geral de login do Supabase muda. Ela vale também para os usuários do app; o painel controla a própria sessão no servidor.
  • Sem "Esqueci a senha" no painel. A recuperação é feita pelo painel do Supabase, que só o senhor acessa.
  • A sessão fica guardada só na aba, nunca no endereço da página.
  • Alterações pedem um código novo quando a última verificação tem mais de 15 minutos.
  • Cores só dos tokens do painel, 6 idiomas, português formal.

1. Hoje | Proposta

Hoje o navegador abre uma caixa pedindo o token de administrador (desenhada aqui com as cores do painel; a aparência real é a do navegador). Na proposta, o painel tem a própria tela de entrada.

2. Código de verificação (toda entrada)

Depois da senha, o código de 6 dígitos do aplicativo autenticador. Sem o código correto, nenhum dado é carregado.

3. Primeira vez: ativar o código

Aparece uma única vez, para uma conta autorizada que ainda não tem autenticador. O código QR abaixo é ilustração; o real é gerado pelo Supabase e mostrado só nesta tela. Nos dois temas o código fica escuro sobre fundo claro (tokens do tema claro), porque muitos aplicativos autenticadores não leem um código invertido.

5. Conta sem acesso · Sessão expirada

Conta sem acesso: entrou com senha e código, mas não está na lista. Sessão expirada: passou o tempo máximo (pergunta 2) ou a sessão foi recusada pelo servidor. Nos dois casos, nenhum dado aparece.

6. Código antes de uma alteração

Ao conceder Premium, marcar conta de teste ou reenviar e-mail, se a última verificação tiver mais de 15 minutos, o painel pede o código de novo antes de enviar. Ler os números nunca pede.
