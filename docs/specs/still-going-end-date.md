- source: founder 2026-10-15 — "quando o aplicativo pergunta se o protocolo ainda está sendo feito, dá a opção para o usuário… colocar no aplicativo que dia que esse protocolo acaba" (Goli, a daily vitamin he takes for months, was asked again and again); picture docs/design/a121-still-going-end-date.html (captures docs/design/a121-telas/) — "aprovado, A, pode". Ledger: docs/decisions.md 2026-10-15 (A-121) and "2026-10-15 — decided by logic for A-121" (DL-109…DL-117).
- related: AD-82 (course-end question, Q5 B), AD-95 (schedule history), DL-87 (inactivity end), DL-99 (a deliberate end is dated at the tap), A-122 (the check must wait for the startup download), A-115 (Fold right page), DV-202 (one Today sheet at a time), DV-249 / DV-250 (clear that never syncs, Restart copy).
- journey review + wiring map folded in (research/09): 2026-10-15 — journey review findings F1–F15 (grok/306 item 4) and docs/product/research/09-protocol-dates-wiring.md (60 consumers, owners, SG-11…SG-27, DV-244…DV-250). F11, F12, F13 → SG-28, SG-29, SG-30. One founder question open: F5 (open-ended protocols, see the end of this file).
- naming: the column is `protocols.ends_on`, the **planned end** (a local day `YYYY-MM-DD`). "End date" in this checklist means the planned end, never `ended_at` (the day a protocol was ended).
- sync rule changed by the Gate B review (2026-10-20, differs from DL-115 "always sent, NULL included"; the chair records it in docs/decisions.md): `ends_on` is sent only when THIS phone changed it (local marker `ends_on_changed`, set by setPlannedEnd / continueCourse, cleared when the cloud accepts the push), on a first insert, or with a whole-row write (re-insert / revive). A clear still goes up (NULL is sent when the marker is set). Any other edit (a capsule dose, "Continua") never sends a stale value over another phone's date; the push reply and the pending-row merge take the cloud's value, except a date still waiting for the column (optional_pending).
- code (expected): screens/TodayScreen.js (prompt, end-date step, course-end question), screens/ProtocolsScreen.js (ProtocolDetail row), screens/components/ProtocolParts.js (DTWheel range), lib/schedule.js (`courseState`, S-15, the only reader of `ends_on`), lib/protocolEnd.js (`setPlannedEnd`, `inactivityDue`, `endNow`, Restart allow-list), lib/wheelPick.js (range option), lib/schema.js + lib/database.js + lib/syncMappers.js + lib/syncCore.js / lib/sync.js (new regular synced column), a Supabase migration (column + `protocols_blank_purged` trigger), i18n ×6.
