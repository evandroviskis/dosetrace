# Adherence report for a third person (relatório de adesão claro para o médico)

- source-spec: docs/design/relatorio-adesao.html (approved by the founder 2026-11-24 13:12 EST, Second Brain 02-decisoes.md: "Concordo também com as suas propostas do relatório de adesão e da adição do nome")
- purpose: the report (Settings › Adherence report) goes to a third person, usually a doctor, who never saw the app. Every number comes in a sentence that explains itself, in the third person; the top says what the report is and where it comes from; "Como ler este relatório" defines each term once. The numbers are the same as today (lib/adherenceReport, lib/doseStreak, the vial count). Nothing is interpreted (product guardrail, AI hard line).
- decisions applied: text + A4 PDF, PDF the main button (founder 2026-11-24); the adherence PDF stays free like today's text (not answered by the founder; the recommendation stands, he can change it); the labs/vaccines PDF also carries the full name, with the same sheet first; in-app words (Dose concluída / pulada / perdida) do not change, only the report; the nickname (display_name) is never printed in a report; the full name is the new user_metadata key report_name (never full_name, which Google writes by itself), empty for everyone at first, never filled from Apple or Google; the profile move to a synced table is feat/profile-synced (same release), so this branch reads and writes both names only through lib/profileName.js (getNickname, getReportName, saveReportName, reportNameFields).
- out of scope here: the "Em jejum / Com refeição" counts and the observations (branch feat/dose-observation). The builder has one named hook for per-protocol extra sections (AR-22) so that branch plugs in after merge; until then the "what this report is" block and "Como ler" leave out the marks and observations wording.
- checklist-signed: pending (the picture was approved 2026-11-24; this checklist is derived from it row by row)
- committed-to: next build (approved → next build)
