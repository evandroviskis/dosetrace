# Adherence report for a third person (relatório de adesão claro para o médico)

- source-spec: docs/design/relatorio-adesao.html (approved by the founder 2026-11-24 13:12 EST, Second Brain 02-decisoes.md: "Concordo também com as suas propostas do relatório de adesão e da adição do nome")
- purpose: the report (Settings › Adherence report) goes to a third person, usually a doctor, who never saw the app. Every number comes in a sentence that explains itself, in the third person; the top says what the report is and where it comes from; "Como ler este relatório" defines each term once. The numbers are the same as today (lib/adherenceReport, lib/doseStreak, the vial count). Nothing is interpreted (product guardrail, AI hard line).
- decisions applied (chair 2026-11-24): the newer Edit profile copy (picture 19a9d92f); English dates keep the month name (decided by logic); no page numbers in the PDF (technical limit, accepted). Earlier: text + A4 PDF, PDF the main button (founder 2026-11-24); the adherence PDF stays free like today's text (not answered by the founder; the recommendation stands, he can change it); the labs/vaccines PDF also carries the full name, with the same sheet first; in-app words (Dose concluída / pulada / perdida) do not change, only the report; the nickname (display_name) is never printed in a report; the full name is the new user_metadata key report_name (never full_name, which Google writes by itself), empty for everyone at first, never filled from Apple or Google; the profile move to a synced table is feat/profile-synced (same release), so this branch reads and writes both names only through lib/profileName.js (getNickname, getReportName, saveReportName, reportNameFields).
- out of scope here: the "Em jejum / Com refeição" counts and the observations (branch feat/dose-observation). The builder has one named hook for per-protocol extra sections (AR-22) so that branch plugs in after merge; until then the "what this report is" block and "Como ler" leave out the marks and observations wording.
- integration 2026-11-24 (integration/pacote-2026-11, the dose observation in the same release): the marks and the observations are plugged in through AR-22 (lib/doseObservation reportObservationSections from observationSummary, wired in Settings), in the words of the approved picture docs/design/relatorio-adesao.html ("Doses registradas como tomadas em jejum (marcado pela pessoa): 27 de 29", "Observações escritas pela pessoa", no "Sem marca" count) and part 4 of docs/design/dose-jejum-refeicao-treino.html; the "what this report is" block and "Como ler" now carry the picture's marks and observations wording. No row changed its meaning; the evidence is added to AR-1, AR-13 and AR-22.
- checklist-signed: 2026-11-24 19:12 EST by the founder in the conversation ("4 aprovo", answering "listas de aceitação com o desenho da observação corrigido"; admin panel Decisões tab item 29, option "A) Assinar as três"; Second Brain dosetrace/02-decisoes.md 2026-11-24 19:12); the picture was approved 2026-11-24 and this checklist is derived from it row by row
- still open after the signature (noted 2026-11-24): the device-proof notes stay as they are and are checked before publication. AR-23: Android (Fold / S25) not driven yet, the name sheet with the keyboard to be eyeballed on the Fold; AR-12: the asterisk notes not seen on a device with a held-back dose (covered by the test only).
