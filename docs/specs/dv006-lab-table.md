# Lab stars and test labels in a synced table — DV-006 (1.3.2 part)

- source: founder 2026-10-20 (docs/decisions.md): "DV-006 deviation accepted: lab stars and labels stay in user_metadata (merge-on-write, refused visibly offline) in 1.3.1; the synced table ships in 1.3.2." Register row: docs/product/DIVERGENCES.md DV-006 (S1, AD-02). The 1.3.1 part: commit 1499933 (lib/bodyPrefs.js, __tests__/dv006BodyPrefsMerge.test.js), merged in bd9581f.
- decided by logic (CLAUDE.md "never lose user-entered data"; "writes merge, never clobber"; the reality-check move off user_metadata, lib/realityCheck.js, is the precedent):
  - one row per starred marker (grouped by the canonical marker key, as 1.3.1) and one per label of a test (keyed by the report date, as today — re-keying labels by card is DV-075, not this item);
  - removing a star or a label is a tombstone (removed_at), never a deleted row, so the one-time copy can never bring it back; starring again clears removed_at on the same row;
  - the copy from user_metadata runs on the phone only after this phone read the cloud table in full, inserts only values whose key has no row (live or removed), and never changes or deletes user_metadata; it is confirmed in user_metadata (lab_prefs_migrated, that one key) only when every copied value is in the cloud; until then the metadata values without a row are still shown;
  - while the cloud table does not exist (the migration file is not applied: PGRST205 / 42P01) the app keeps the 1.3.1 path exactly, and nothing else in the sync changes; a lab star or label waiting to be sent counts with the lab values in the "not backed up" texts (no new word).
- not visual: the screen, its texts and both themes are unchanged (no new string); what changes is where the values are kept and that a star or label made offline is kept instead of refused.
- code: lib/labPrefsStore.js (rules), lib/labPrefs.js (app wiring; the one read / write API: loadLabPrefs, saveLabStar, saveLabTags), lib/syncCore.js (lab_prefs in TABLES; LATE_TABLES, missingCloudTable, cloudTableReady), lib/syncMappers.js, lib/schema.js, lib/changeSeq.js, lib/database.js (sign-out wipe, local owner), lib/unsentSummary.js, screens/BodyScreen.js, supabase/functions/delete-user/index.ts (list only; it already tolerates a missing table), supabase/migrations/20261026000000_lab_prefs.sql (NOT applied).
