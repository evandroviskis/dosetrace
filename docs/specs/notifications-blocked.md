# Notifications blocked on the phone — a short sheet

- source: founder 2026-10-20 — "Pode seguir com as suas recomendações em todos"; docs/decisions.md 2026-10-20 "1.3.2 recommendations accepted: … a short sheet when notifications are blocked on the phone".
- purpose: when the phone blocks DoseTrace's notifications, no reminder can arrive — and nothing in the phone tells the person. Today already shows the "Seus lembretes estão bloqueados" card (RC-6, docs/specs/reminder-check.md); this adds one short DoseTrace sheet, once per state change, that says so plainly and opens the phone's settings. Never nagging.
- decided by logic (founder may override): "blocked on the phone" is the permission the phone reports as denied — never asked yet (undetermined) or unreadable is not blocked (DV-214); the sheet follows Today's card rule (dose reminders on, not Silent mode, a protocol with a reminder time: RC-6, BR-4 / AD-25); the button opens the same system screen as the Reminder check's notifications row (lib/notifications openReminderFix('notifications')); the state is kept on this phone (the permission belongs to the phone, not the account); the Android reminder setup screen (SP-5, shown once) goes first, since it lists Notifications too; a fresh "Não permitir" in the system dialog is a state change too, so the sheet can follow it once.
- no new visual pattern: the DoseTrace sheet (DTSheet: icon in a well circle, title, body, "Agora não" | primary), as Today's other sheets.
- code: lib/notifBlocked.js (the rule and the sheet), screens/TodayScreen.js (checkNotifBlocked, read with the reminder health), i18n nb_* ×6.
- checklist-signed: pending (founder)
- committed-to: 1.3.2 (founder 2026-10-20, "1.3.2 recommendations accepted")
